# ChainOps AI — Domain Models

Source of truth: [src/types/domain.ts](../src/types/domain.ts). Status enums and business-ID
conventions also live there. **All models below in "Existing" exist in code today (after Phase 3).**
Models in the "Planned" section do **not** exist yet.

Conventions used by every model:

- Each entity has an internal `id` (uuid-style string, e.g. `prj-goapass`) **and** a
  human-readable `businessId` (e.g. `PRJ-1001`) generated by `nextBusinessId(prefix)`
  ([src/server/core/domain/ids.ts](../src/server/core/domain/ids.ts)), which increments a
  per-prefix counter starting after the seed baselines (`COUNTER_SEED` in
  [src/server/seed/demo-data.ts](../src/server/seed/demo-data.ts)).
- Timestamps are ISO-8601 UTC strings (`Iso8601`).
- Persistence is **in-memory only** (globalThis singleton store); everything is lost on server
  restart, and `POST /api/demo/reset` restores the deterministic seed.

## Existing models (Phase 1–3)

### Workspace
- **Purpose:** single-tenant demo workspace metadata.
- **Fields:** `id`, `name`, `plan: "demo"`, `mode: "simulation"`, `seededAt`.
- **Relationships:** none (singleton).
- **Validation:** none at boundaries (not user-editable).
- **Persistence:** built in seed (`workspace`), readable via services.
- **Usage:** dashboard/config surfacing; several services hardcode "simulation" labels.

### User
- **Purpose:** workspace member identity (display only — **no authentication exists**).
- **Fields:** `id`, `name`, `email`, `role` (`owner|admin|engineer|viewer`), `avatarHue`.
- **Relationships:** referenced by name in `Project.ownerName`, deployment `triggeredByName`,
  activity `actor`.
- **Validation:** none (seed-only; no user CRUD API).
- **Persistence:** seed `users` array.
- **Usage:** activity attribution, avatar rendering in the shell.

### Project
- **Purpose:** a deployable application/repository under management (the core aggregate).
- **Fields:** `id`, `businessId`, `name`, `slug`, `description`, `repoUrl` (`owner/repo`),
  `defaultBranch`, `status` (`active|archived`), `environment` (`production|staging|development`),
  `ownerName`, `serviceIds[]`, `chainIds[]`, `createdAt`, `updatedAt`, `archivedAt`.
- **Relationships:** 1→N `Service` (denormalized `serviceIds`), N↔N chains (`chainIds`),
  1→N `AnalysisJob`, `Deployment`, `Incident` (via `projectId` / `affectedProjectIds`);
  referenced by `ActivityEvent.refType: "project"`.
- **Validation:** Zod create/update schemas in `ProjectService` (name length, slug format
  `^[a-z0-9]+(-[a-z0-9]+)*$`, `repoUrl` pattern, `ENVIRONMENTS` enum).
- **Persistence:** `InMemoryProjectRepository` (extends generic `InMemoryRepository<T>`).
- **Usage:** full CRUD + archive/restore, search/filter, detail bundle (Overview / Analysis /
  Activity / Settings tabs), slug-rename propagation to deployments/incidents/activity.

### Service
- **Purpose:** a deployable component of a project (api/worker/frontend/contract).
- **Fields:** `id`, `businessId` (`SVC-…`), `projectId`, `name`, `kind`
  (`api|worker|frontend|contract`), `tier` (`tier-1|tier-2|tier-3`), `environment`,
  `teamName`, `createdAt`.
- **Relationships:** N→1 `Project`; referenced by `Deployment.serviceId`,
  `Slo.serviceId`, `Incident.serviceIds`, `ServiceHealthSnapshot.serviceId`.
- **Validation:** none at boundaries (seed-only; no Service CRUD API).
- **Persistence:** store array (seed).
- **Usage:** dashboard health table, SLO targets, incident blast radius, deployments.
  `chainTouchingServiceIds` (seed export) drives chain-failure blast radius in sim.

### AnalysisJob
- **Purpose:** repository analysis run (Phase 3) over a project's repo.
- **Fields:** `id`, `businessId` (`ANL-…`), `projectId`, `repoUrl`, `ref`, `status`
  (`queued|running|complete|failed`), `stageIndex` (0–6 into `ANALYSIS_STAGES`), `queuedAt`,
  `startedAt`, `finishedAt`, `analysis` (`RepositoryAnalysis | null`), `error`,
  `source` (`demo-analysis|real-integration`).
- **Relationships:** N→1 `Project`.
- **Validation:** start-input validated in `AnalysisService.start` (project exists, not
  archived, no in-flight duplicate); result validated by `repositoryAnalysisSchema` (Zod) in
  the analyzer port before being materialized.
- **Persistence:** `InMemoryAnalysisJobRepository`.
- **Usage:** project Analysis tab; **settle-on-read** progression — `AnalysisService.getById`
  advances stages every `STAGE_ADVANCE_MS = 1500` ms of real time and materializes the
  analyzer result at completion. UI polls and renders stage progress.

### RepositoryAnalysis (value object, from analyzer port)
- **Purpose:** immutable analyzer output attached to a completed job.
- **Fields:** validated by Zod in the port: repo summary, detected languages/frameworks,
  infra manifests, reliability/security checks, recommendations. Carries provenance
  `source: "demo-analysis" | "real-integration"`.
- **Relationships:** embedded in `AnalysisJob.analysis`.
- **Persistence:** embedded JSON in the job row.
- **Usage:** Analysis tab result rendering.

### Deployment
- **Purpose:** a release of a service version into an environment (Phase 4's subject).
- **Fields:** `id`, `businessId` (`DEP-…`), `projectId`, `serviceId`, `serviceName`
  (denormalized for display), `version`, `gitSha`, `environment`, `trigger`
  (`manual|pipeline|auto-rollback`), `status` (10-value machine — see below), `steps`
  (`DeploymentStep[]` from canonical `DEPLOYMENT_STEPS`), `logs` (`DeploymentLog[]`),
  `simulatedFailureStep`, `isSimulatedRun`, `canary` (`{stablePct, canaryPct} | null`), `durationMs`,
  `triggeredByName`, `createdAt`, `updatedAt`.
- **Relationships:** N→1 `Project`, N→1 `Service`; referenced by `ActivityEvent`.
- **Validation:** transitions guarded by `canTransitionDeployment` — invalid transitions throw
  `InvalidTransitionError`.
- **Persistence:** store array (seed + API-created rows).
- **Usage:** dashboard recent-deployments, project activity, deployment center and live detail.
  The deterministic demo provider advances created deployments on reads; state is in memory.

### DeploymentLog
- **Purpose:** structured demo-provider messages recorded during a deployment lifecycle.
- **Fields:** `id`, `at`, `level` (`info|warning|error`), `message`.
- **Persistence:** embedded in `Deployment.logs`.
- **Provenance:** all runtime entries are simulated; no build or infrastructure provider is contacted.

### DeploymentStep
- **Purpose:** one pipeline step of a deployment.
- **Fields:** `id`, `name`, `status` (`pending|running|success|failed|skipped`), `startedAt`,
  `endedAt`.
- **Relationships:** embedded list in `Deployment.steps`.
- **Usage:** seed builds them from `DEPLOYMENT_STEPS` (10 canonical step names); API-created
  deployments start all steps `pending`.

### CanaryWeights
- **Purpose:** traffic split during a canary rollout.
- **Fields:** `stablePct`, `canaryPct`.
- **Usage:** embedded in `Deployment.canary`; seeded and simulated rollout weights are displayed
  in the deployment detail view.

### PipelineRun / PipelineStage
- **Purpose:** a simulated validation workflow that gates creation of a deployment.
- **PipelineRun fields:** `id`, `businessId`, `projectId`, `serviceId`, `serviceName`, `version`,
  `gitSha`, `environment`, `status` (`queued|running|success|failed|cancelled`), `stages`,
  `deploymentId`, `failureStage`, `startStageIndex`, `startedAt`, `completedAt`, `createdAt`,
  `updatedAt`.
- **PipelineStage fields:** `id`, `name`, `status` (`pending|running|success|failed|skipped|cancelled`),
  `startedAt`, `endedAt`, and deterministic demo `log[]`.
- **Lifecycle:** settle-on-read progression through Source, Lint, Unit tests, Integration tests,
  Contract tests, Security scan, Build, Staging, Smoke tests, Canary and Production. Production
  success creates a linked queued deployment through `DeploymentService`.
- **Persistence/provenance:** in-memory only; no external CI system or repository is contacted.

### Incident
- **Purpose:** a service degradation/disruption event.
- **Fields:** `id`, `businessId` (`INC-…`), `title`, `severity` (`sev-1`…`sev-4`), `status`
  (`detected|investigating|mitigating|monitoring|resolved`), `serviceIds[]`,
  `affectedProjectIds[]`, `detectedAt`, `resolvedAt`, `summary`, `impact`.
- **Relationships:** N↔N `Service` and `Project`; 1→N `IncidentEvent`.
- **Validation:** transitions guarded by `canTransitionIncident`; resolving sets `resolvedAt`.
- **Persistence:** store arrays (seed).
- **Usage:** dashboard rail, activity; read-only today (no create/transition API routes yet —
  transitions only exercised via service methods/tests).
- **State machine:** `detected → investigating|resolved`;
  `investigating → mitigating|monitoring|resolved`; `mitigating → monitoring|investigating|resolved`;
  `monitoring → investigating|resolved`; `resolved` terminal.

### IncidentEvent
- **Purpose:** timeline entry on an incident.
- **Fields:** `id`, `incidentId`, `at`, `kind` (`detection|alert|status-change|ai-analysis|
  action|mitigation|resolution`), `message`, `actor` (`system|ai|<user name>`).
- **Usage:** incident detail timeline; appended by `IncidentService.transition`.

### Slo
- **Purpose:** service-level objective for a service.
- **Fields:** `id`, `businessId` (`SLO-…`), `serviceId`, `serviceName`, `kind`
  (`availability|latency|error-rate`), `targetPct`, `windowDays: 30` (literal type), `description`.
- **Relationships:** N→1 `Service`.
- **Validation:** math validated in `tests/slo.test.ts`; no CRUD API.
- **Persistence:** store array (seed, 5 SLOs).
- **Usage:** `SloService` computes an `ErrorBudget` per SLO from sim snapshots + incident blast
  radius; feeds project list summaries and dashboard compliance.

### ErrorBudget (computed value object)
- **Purpose:** current budget state for an SLO. Not stored — computed per request.
- **Fields:** `sloId`, `targetPct`, `currentPct`, `remainingPct`, `consumedPct`,
  `burnRate1h`, `burnRate6h`, `projectedExhaustionAt`.
- **Usage:** `SloService` / `DashboardService` via pure functions in
  [src/server/core/domain/slo.ts](../src/server/core/domain/slo.ts)
  (`errorBudgetRemainingPct`, `clamp`, `burnRate`, `computeErrorBudget`).

### Chain
- **Purpose:** a blockchain network the workspace operates on.
- **Fields:** `id`, `businessId` (`CHN-…`), `network` (`ethereum|polygon|base|arbitrum`),
  `chainId` (numeric EIP-155 id), `blockHeight`, `blockTimeMs`, `status` (`HealthStatus`).
- **Relationships:** 1→N `RpcProvider` (via `RpcProvider.chainId` — note: the FK holds the
  **chain's internal id string**, e.g. `chn-base`); referenced by `Project.chainIds`.
- **Validation:** none (seed-only).
- **Persistence:** store array (seed).
- **Usage:** dashboard chain rail; `ChainService` applies a sim failure overlay
  (`rpc-base-b` seeded degraded).

### RpcProvider
- **Purpose:** an RPC endpoint provider behind a chain.
- **Fields:** `id`, `businessId`-less (plain id like `rpc-base-b`), `chainId` (chain's internal
  id string), `name`, `trafficWeightPct`, `status` (`healthy|degraded|down`),
  `latencyP50Ms`, `latencyP95Ms`, `errorRatePct`.
- **Usage:** chain detail data, incident scenario context; sim overlay mutates `rpc-base-b`.

### ActivityEvent
- **Purpose:** append-only audit/audit-log of workspace events.
- **Fields:** `id`, `at`, `kind` (`deployment|incident|slo|chain|chaos|project|system`), `title`,
  `detail`, `refType` (`deployment|incident|slo|chain|project|null`), `refId`, `actor`.
- **Validation:** none at boundary; created only via `ActivityStore.append`.
- **Persistence:** append-only `ActivityStore` (in-memory).
- **Usage:** dashboard timeline, project Activity tab, global activity surfaces.

### Notification
- **Purpose:** user-facing notification (bell menu).
- **Fields:** `id`, `kind` (`ActivityKind`), `title`, `body`, `severity`
  (`info|warning|critical`), `readAt`, `createdAt`.
- **Usage:** topbar notifications menu + unread count. `NotificationService` exposes
  list/unread-count/mark-read, but **no API route exposes notifications yet** (the shell
  reads them server-side); mark-read has no UI/API path currently.

### MetricPoint (value object)
- **Purpose:** one timestamped metric sample.
- **Fields:** `t` (ISO time), `v` (number).
- **Usage:** produced by the simulation sampler for charts (`sample` module); consumed
  indirectly through snapshots.

### ServiceHealthSnapshot
- **Purpose:** point-in-time health/traffic/latency/resource metrics for one service.
- **Fields:** `serviceId`, `serviceName`, `projectId`, `status` (`HealthStatus`), `availabilityPct`,
  `requestRatePerMin`, `errorRatePct`, `p50Ms`, `p95Ms`, `p99Ms`, `cpuPct`, `memoryPct`.
- **Usage:** generated by `SimulationEngine` per service; consumed by DashboardService,
  SloService, ChainService blast radius. Buckets sample against **real time** (`simNowMs`), so
  the dashboard moves on refresh.

### ChaosExperimentType / ChaosRun
- **Purpose:** allowlisted simulated experiment kinds and persisted in-memory run result, including target, duration, intensity, blast radius, status and incident link.
- **Fields:** union of 9 experiment kinds (`pod-failure`, `rpc-failure`, `network-latency`,
  `packet-loss`, `cpu-stress`, `memory-pressure`, `db-failure`, `traffic-spike`,
  `deployment-regression`).
- **Usage:** **type-only** today; no entities, persistence, UI, or tests.

## Planned models (NOT yet implemented — future phases)

These do **not** exist in `src/types/domain.ts` or anywhere else. They are listed per
[docs/ROADMAP.md](ROADMAP.md) so agents plan shapes early, but must not be created until the
owning phase.

| Planned model | Phase | Intended shape (sketch) |
|---|---|---|
| `Anomaly` / `CapacityForecast` | 10 (AI Ops) | anomaly detection results over metric series; forecast series (not yet implemented) |
| `ChaosExperiment` | 9 (Chaos) | reusable named experiment definitions/catalog; current executions use implemented `ChaosRun` records |
| `DeploymentLog` | 4 (Deployment Engine) | streaming step logs attached to a `Deployment` during progression |
| `DeploymentProvider` / `TelemetryProvider` / `ChainProvider` / `AIProvider` / `PolicyEngine` | 4/6/10/11 | provider ports in `src/server/core/ports/` with `simulated/` adapters, following the `RepositoryAnalyzer` pattern (`isDemo` flag, provenance in results) |

**Marking rule:** anything from this table must be introduced with an explicit "PLANNED /
implemented in Phase N" note in docs, or simply be absent until implemented — never implied
to exist.
